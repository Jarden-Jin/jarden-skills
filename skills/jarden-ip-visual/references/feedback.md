# 回改协议与反馈边界

用户说“不够高级”“再可爱一点”不是换角色、换品类或撤销全部确认的授权。先把反馈保存为可执行、可复核的结构，再做局部制作。

## 每轮保存

在 `project.feedback` 或对应交付回执中尽量记录：

```json
{
  "raw": "用户原话",
  "interpretation": "Agent 对可观察问题的解释",
  "change": "具体改法",
  "keep": ["明确保持的身份、配色、构图或图位"],
  "scope": {"subjects": ["角色"], "slots": ["detail"], "delivery_id": "D0005"},
  "baseline": "用于对比的交付或图位",
  "verification": ["实际复查结果"]
}
```

不要求为每个小改动硬编码新字段；但至少能从原话追到改法、保持项和影响范围。用户已经明确的信息不重复提问，模糊反馈不自动视为撤销此前决定。

## 先解释再执行

1. 定位可观察原因：材质反光、缝线、配色、构图、尺度、人物动作、光线或图序。
2. 说明准备改什么、不改什么，以及会受影响的图位或角色。
3. 明确改法直接执行；只有两种解释会改变角色身份、产品形态或大范围结构时，先问当前冲突。
4. 修改后用同主体、同图位、可比较尺寸的前后图核对，不拿缩略图或不同阶段硬拼结论。
5. 受影响的实际输出重新做必要物理审查；没改的图位保留有效原结果，不因整轮重做全部丢图。

## 身份与创作分开

- 用户对表情、材质或配饰的偏好，不能自动改五官结构、主色区或系列记忆点。
- 用户确认身份变化时，记录新的 `brief.decisions` 与来源；旧身份报告失效，新的身份报告需覆盖变化后的图。
- 创作方向的大幅重做可触发身份复核，但创作“更像爆款”“更适合传播”不能覆盖物理失败、缺图或事实冲突。
- 文案修改只失效文案与图文对应检查；不重审物理，也不自动改写已定身份。

## 传播素材的反馈

传播建议必须落在可检查的对象上：封面是否第一眼认出、前后图是否提供实质差异、生活场景是否能代入、每张是否增加信息、文案是否有依据、tag 是否相关。不要承诺“一定爆”“保证销量”或把平台推荐写成已验证事实。

参考分析可用于提炼图序和文案结构，但不能复制参考帖的品牌、角色造型、图片文字或作者署名。四类笔记的具体图序仍以对应 `references/note-types/` 为准。

## 停止信号

同一意见连续多轮无改善、前后要求冲突、已触及费用/时间边界，或反馈已指向新的方向时，停止自动消耗生图预算。展示：

- 当前完成度与保留项；
- 未解决的问题和报告类别；
- 两到三个小范围可选路径、代价与需要用户确认的点。

停止不是批准。轮数耗尽、审查缺报、物理 `uncertain` 或用户沉默都不能自动把失败改成通过。
