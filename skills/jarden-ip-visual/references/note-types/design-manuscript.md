# IP 设计手稿

适合设计师展示从想法到产品的设计能力。首图先让人看到成品，过程图负责解释设计。

## 图片顺序

| 图位 | 内容与作用 |
| --- | --- |
| cover | 成品首图：克制背景、角色全身清晰；只有用户明确要提案字标才加英文字、已确认年份与署名 |
| lineup | 多角色或配色款平铺，同模板与相同机位，单角色可省 |
| turnaround | 正、侧、背三视图，清楚交代结构与配件位置 |
| manuscript | 原始手稿与成品对位，或草图→设计→材质效果的递进 |
| scene-1 | 从人设推导的世界观场景，暖光或明确的叙事光线 |
| extension-1 | 表情贴纸、壁纸、包装或合适的产品延展 |

不要拿手稿当首图，不要每页都塞满海报大字。用留白与图的大小建立重点。

## 角色和版式

角色可有固定的小脾气表情与清楚轮廓，头身比根据输入决定。参考帖的比例语言可以借鉴，具体五官和配件不复制。

用户明确要设计提案字标和署名时用程序添加，可用 compose.py poster；默认不加提示性声明。英文名未提供时可建议原创英文名，未经认可不当成注册品牌。

三视图逐视角生成，正面沿用定稿；侧面与背面要符合正面的结构。不能横向拉伸正面图充当侧面。

手稿页要让人看懂平面设定与成品的对应，或从草图到设计、材质的实质变化。使用用户原稿或当前项目真实留存的过程；两张近似成品渲染不能只因来自不同轮次就充当手稿过程。只有文字或立体概念时，补一张能说明轮廓、色区和配件关系的二维设定，在文案与HTML注明本轮补充的 AI 设定，不倒填成历史手绘，不默认把声明印到图里。

不伪造「打样实物」或已经发生的工厂流程。

## 世界观场景

从记忆点反推小环境与动作，给角色一个生活理由。装饰围绕故事服务，不把通用森林、云朵或花朵当作固定模板。

场景仍有可信材质和空间投影。奇幻设定可以原创，但角色不能从实体手办突然变成二维贴纸。

## 标题与正文

标题建议12到20字：「前缀 | 主体」，最多一个 emoji。

正文：灵感与痛点 → 角色个性 → 关键设计选择 → 本次做到的阶段 → 请读者评价。写真实决策，不罗列提示词。

说明三视图与材质图是设计呈现，不能声称已达到工程打样条件。

## Tag 顺序

建议8到10个：

1. 相关活动词；没有适用活动就跳过。
2. #IP设计、#原创IP 等创作词。
3. 实际品类。
4. #AI 或实际使用的工具；没有确认工具名就不编。
5. 人群或情绪。
6. IP 名称。

## 验收

首图是成品；三视图一致；手稿有真实来源且能解释设计变化或平面到成品的对应；至少一个世界观场景；延展与角色有关；没有拼写错误或伪文字。按图上实际提供的信息验收，不只检查图位名称。
