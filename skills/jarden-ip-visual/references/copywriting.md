# 标题、正文与 Tag

文案依据已生成的图、用户提供的信息和项目进度来写。它是可直接复制的发布草稿，不是运营方法课。

## copy.json

在项目根目录保存：

```json
{
  "title": "这群小伙伴终于有样子了",
  "body": "写当前项目的灵感、角色、设计细节与真实进度。\n结尾邀请读者选择。",
  "tags": ["#原创IP", "#角色设计", "#毛绒玩具"],
  "ai_disclosure": "AI 生成的设计效果图，实物以打样为准。",
  "image_text": "none",
  "overlays": {}
}
```

例子只说明结构。标题和正文重新创作，tag 按实际类型补足与排序；不要复制例子当成每个项目的成稿。

## 干净图片与说明分离

默认所有品类的图片不加附注、提示条或水印；特别不写“AI效果图、非实拍、仅供尺度示意、实际尺寸待定、道具不随附”等声明。未知规格不为凑信息页而逐项写进图中，换成可见细节或用法；需要说明的事实写在正文、HTML 制作说明和 manifest，发布时按平台要求选择 AI 声明。清理图字不等于冒充实物摄影。

`image_text` 默认 `none`，非空 overlays 会被拒绝。只有用户明确要求图上文字时设置 `image_text=user-approved` 并按已确认内容填 overlays；直接使用 compose.py 写字也须加 `--image-text user-approved`，不要替用户批准。独立信息卡/设计标注也是用户确认的例外，不自动给每张照片加说明。已烘焙进原图的字需要编辑处理后重审，打包器不会 OCR 或自动擦字。

## 内容预算

| 项目 | 本 Skill 使用的预算 |
| --- | --- |
| 标题 | 20字以内；各类型有更细的建议 |
| 正文 | 含效果图声明1000字以内，作为保守交付预算，当前平台限制未经脚本验证 |
| Tag | 3到10个，不重复，每个以#开头，无空格 |
| 图片 | 3:4竖版，默认1080×1440；一篇最多18张的交付预算 |

这些值是素材检查规则，不能冒充已核实的平台实时政策。发布前以当前账号的发布页校验为准。

计数字符时 FE0F 和 ZWJ 不计数。复杂 emoji 在平台的计算可能不同，标题留余量。

## 四类的 Tag 类别顺序

| 类型 | 类别顺序 | 建议个数 |
| --- | --- | --- |
| 同系列合集 | 创作大词→题材→方法或工艺→情绪梗→形态或人群 | 8到10 |
| IP 设计手稿 | 相关活动→IP设计与原创→品类→AI与实际工具→人群情绪→IP名 | 8到10 |
| 单个玩偶多维展示 | 已提供的品牌→产品名→题材→品类→泛可爱或情绪 | 3到7 |
| 多个玩偶多场景展示 | 已提供的品牌→品类→原创设计→情绪梗→用途人群→相关节日活动 | 6到10 |

无品牌、活动或工具信息就跳过该类别。用其他相关词补足合理数量，不发明品牌、不蹭无关活动。

Tag 是有序列表。脚本检查格式、数量和重复；语义是否相关、类别顺序是否正确由 Agent 自检。

## 事实与语气

- 原创、授权、打样、实物、库存、价格、发售时间和合作关系都需要依据。没有依据时用设计效果图、计划或待定表述。
- 用户给的草图在过程页里可以署用户提供的名字；不猜真实姓名、不借用参考帖的作者名。
- 不写虚构的消费者评论、销量、获奖或「必爆」保证。
- 图是 AI 生图就不能自称亲手拍的实物开箱；文案中的使用场景应在图里能找到。
- 短句与具体细节优先，不堆形容词。系列文案列出全部角色名，便于挑款。
- 不放站外联系方式或未经请求的导流；图片正文不抄参考帖。

## 交付前检查

标题能在一眼内说清主题；正文承接图序；产品信息未知处保留待定；tag 与图文相关且顺序正确。

效果图声明放进 caption.md，发布页仍需按平台要求选择 AI 声明。当前脚本不操作账号或发布内容。
