# 场景图的零上下文物理审查

这是强制的独立视觉物理检查，不是数值物理引擎。不能声称已经做刚体仿真、计算真实质量或证明量产结构。程序只验证审查格式、覆盖范围、执行者声明和图片哈希，不能证明 Agent 真的隔离或看过图；执行者必须使用宿主实际提供的独立 Agent 能力。

## 何时审

- 每张关键场景备选和整组图片都审，不只审选中的封面。手托、尺度、细节、群像、产品棚拍、世界观和生活场景中的小五金也不能漏掉。
- 编辑、重生、拼版、换背景、平面透视合成后，实际输出重新审；不能沿用素材祖先的批准。只有字节完全相同、产品形态相同的文件可以复用已有判定。
- 所有手动 `final` 都要审，不能靠改 role 或 method 绕过。纯二维设定页在不适用项说明原因，但仍检查实际画出的产品关系。
- 打包可能裁切、补边或加用户指定文字，因此排版后实际发布图也要审；缩放后的新像素不是原图审查自动覆盖的范围。

## 送审：不继承制图者上下文

先建立最小包，命令不会改原图、选择或发帖状态：

```text
<python> <skill>/scripts/physics_review.py prepare <项目> --producer <制图执行者ID> --round <轮次>
<python> <skill>/scripts/physics_review.py prepare <项目> --producer <制图执行者ID> --images <项目内图路径> <另一路径>
```

用宿主支持的隔离 Agent 新建审查者，明确不继承对话，只把输出中的 `packet` 目录交给它。每次新图或返修使用新的零上下文审查者；同一批可逐张输出。不要传作者的生成提示词、创作理由、喜欢哪个、历史通过或客户批准，也不要预告应该通过或失败。不复用已经听过作者解释的审查者。

包中只有匿名图片、哈希、已确认的产品形态和通用检查任务。脚本用 Pillow 检查并拒绝文本、作者 EXIF、XMP 等额外元数据，只放行数值型色彩/尺寸/方向等技术字段，避免图片文件夹带作者提示词；出现时先另存仅像素副本并将其登记为实际待定稿，再重新送审，不能只改后缀或哈希。`mapping.json` 在包外，只供导入结果时定位；不能把整个项目交给审查者。指定实际 Agent 标识，不拿“独立”作为自己签名。

宿主没有独立 Agent 或看图能力时，保留待审图并明确停止在物理验收，不以作者自检或用户选定代替。请用户换到有相应能力的宿主，不自动外发给未批准的新服务。

## 审什么

| 检查键 | 必须解释的可见证据 |
| --- | --- |
| gravity_support | 重力、支撑点、重心稳定性与连续载荷路径；悬挂是否真的挂上，摆放是否有接触 |
| connections_materials | 环、链、绳、织带等连接的闭合和穿套；自由转动件能否保持姿态；柔性材料的下垂、松紧和形变 |
| contact_anatomy | 手指结构、承托/抓握、压痕、遮挡关系；没有融合、穿模或不能解释的接触 |
| lighting_perspective | 光源、反射、接触影、空间透视和真实厚度是否相容 |
| overall_realism | 局部关系是否共同可信；不能用“整体好看”抵消关键缺陷 |

自由金属环不必一律平放或垂下，但直立必须有可见且可信的约束、抓握或搭靠。柔软织带穿过环只说明连接，不自动说明它能抗倾倒；不得替图片脑补隐藏硬支架、夹手、胶粘或拍摄瞬间恰好平衡。真实支撑改清楚后，阴影和遮挡也必须对应。该原则同样适用于所有扣件、道具和产品，不固定一种造型。

有明显问题判 `needs_revision`；关键关系遮挡或含混、证据不足判 `uncertain`，两者都阻止推进。不把“可能有一种解释”当通过。明确风格化的虚构元素可按已确认设计判断，但其承托实体产品、人体与硬件的关系仍需可信；未经用户明确要求不以奇幻设定豁免。

普通自然遮挡不自动等于关键关系缺失：围巾遮肩根或微距不见脚，不要求所有内部接缝和全身同时可见。应指出具体可见异常、不连续载荷路径，或本镜头承担的关键连接确因遮挡无法验证，才判失败/不确定。微距的整体可信度仅限当前可见范围，不外推图外稳定或真实强度；漂浮、穿模、断接仍不能靠隐藏支架、胶粘或特殊刚度解释。该范围规则不取消逐图独立 gate，也不覆盖任何历史负评。

## 记录和返修

审查者按包内 task.md 返回逐张 JSON，含实际 reviewer ID、零上下文与实际看图声明、五项证据、判定和具体返修区域。导入：

```text
<python> <skill>/scripts/physics_review.py record <项目> --request <request_id> --report <审查结果JSON>
```

脚本拒绝同一制图者自批、缺图/重复结果、缺检查项、未看图声明、失败项却整体通过或哈希变化。同请求结论封存，重复导入不能改判；旧请求不能覆盖更新判定。选方向前重验整轮已有场景备选，不能因没选某张就忽略它换图或失败。所有判定保存在 `reviews/physics/`，不烘焙到图上。它是可追溯声明，不是加密身份证明或物理正确性保证。

只有 `pass` 才能 `record-round`、`select`、手动 `final` 和正式打包。`uncertain` 不等于可交付。失败只编辑或重生对应图位，保留其他图，换新包再盲审，直到通过；不能用 caption 解释错误。缺图可以 `--allow-missing` 留档，但已有图片不能用这个开关逃避审查。

最后整理：范围已授权可直接 prepare-review（已内含预检），只诊断时单独 dry-run。用不同执行者完成 G1 和 G2：

```text
<python> <skill>/scripts/package_post.py <项目> --prepare-review
<python> <skill>/scripts/contract_review.py prepare <项目> --producer <制图执行者ID> --stage package --images <每张待发布图> --ordered-slots <项目>/<返回的映射文件>
<python> <skill>/scripts/physics_review.py prepare <项目> --producer <制图执行者ID> --images <上一步列出的每张待发布图>
```

新零上下文 Agent 看完后导入报告，再运行 `package_post.py <项目>`；正式输出必须与审过的像素哈希一致。若裁切、字、字体或源图变化，重新准备和审查。失败时不覆盖已有 post，旧项目没有审查记录时也不自动批准。
