# 阶段规则

每轮只解决一个决定。各阶段的差异来自视觉问题，不来自文件名或随意换色。

## 进入阶段

| 输入情况 | 从哪里开始 |
| --- | --- |
| 文字想法、线框、草图、缺少五官或配色的灵感拼贴 | 概念 |
| 完整平面角色，用户明确说设计已确认 | 用 accept-input 登记概念，再进材质 |
| 已认可的产品材质效果图 | 登记概念与材质，再做透明资产 |
| 同一会话的已有项目 | 从 project.py show 的 next 继续 |

没有明确说已定稿，就保留概念确认。局部设计灵感不等于整个角色可直接沿用。

## 概念

输入是用户的平面图与简短意图，输出是同一角色的清楚、完整设计方向。探索默认三方向；明确返修、已定方向或先看一张可用一至两个。

- 先写角色身份：轮廓、体型、五官位置、主要颜色、一个记忆点、性格。
- 草图有明确特征就保留；开放区域才发挥原创。不要把原兔子变成普通熊，或用熟悉的爆款造型填空。
- 多个方向在设计语言上拉开，比如软塌比例、几何体块、表情与配件关系。仅换背景不算概念方向。
- 用清晰的平面着色或干净的概念视图，确保用户看得懂结构；暂不制作最终生活场景。
- 第一个角色通过后，把共同的头身比、眼睛语言、线条和配色范围写入 brief.bible。

## 材质

输入是已选概念，输出是这个产品可对比的工艺或材质方向，数量沿用本轮明确的决定，不为凑满三张重复生图。

- 保持相同的角色身份、机位和画幅；明确指出短绒、卷绒、长毛分区或其他材质差异。
- 材质要符合产品形态：手办有实体块面，毛绒有纤维和缝线，拼图有平面印刷和拼片边缘。
- 不为凑方向改变脸、配色或标志配件。只在用户要改角色时退回概念阶段。
- 图的目标是可信的商业展示；避免游戏建模截图、油亮玩具或无重力悬浮。

## 完整 2D 透明资产

输入是每个角色已选材质，输出是每个角色一张正面完整全身的 PNG。

- 保持选定材质和颜色，裁切留足耳朵、毛尖、脚、绳和扣件的空间。
- 生图工具支持真透明时直接请求，生成后仍检查 alpha。
- 不支持时选一种与主体所有颜色反差明显的纯底色。不要让模型画灰白棋盘格。
- 用 remove_bg.py 去掉背景后检查：毛尖和边缘没有白边或色边，主体没有误删，挂环和手臂中的孔洞没有堵住。
- 把实际 alpha 合成到浅、深两种底色再验边。某些预览器会显示透明区域残留的 RGB，不能仅凭原始预览中的底色或亮边就判失败、重复生图。
- 默认从边缘去底，保留封闭的同色主体区域。只有背景色不在主体上出现时才加 --holes。
- `check_images.py --alpha` 是必要检查，不能替代目视检查。失败就修图或重生，不继续。

## 场景

先按 [产品与镜头](product-and-shots.md) 保存用途、设计尺度与逐图计划。再做关键场景方向，探索默认三方向，明确方向可一至两个；已有通过必要门禁的真实场景基准可直接采用。通过后再出整组，不把方向 A/B/C 当成三张最终笔记。

整组图按笔记类型的图位分工。每张生成前写清：

1. 图位的作用：认脸、尺度、细节、群像、世界观或用法。
2. 出场角色和数量，指定每只角色的参考图；未出场者不进入画面。
3. 一个尺度参照、接触点或悬挂连接，光源与投影一致。
4. 延续的配色、材质、记忆点道具；这一张的新信息。

道具从角色的人设与用途推导；装饰不是越多越好。不要把所有类型都做成统一的白底摆拍。

尺度用可见参照表达，不在成图里贴提示条或待定信息。设计厘米、像素与画面占比分开；手掌不是精确测量。增加角度时保留正面，用 scene-patch 指定新增/修改范围；未知隐藏面先提案确认，不默认建真实三维模型。

每个重物、环扣、链绳、软织带都要有可解释的支撑或垂落关系，不为美观让自由件悬空直立。所有场景备选、整组、局部编辑和合成输出先做独立 G1 实际合同验收，再由另一位执行者走 [零上下文物理审查](physics-review.md)。G2 不带合同和 G1 判词；有问题或不确定只修对应图位再审。用户选定不能豁免。缺少独立能力时保留待审，不推进。

## 选定、补图和重新生成

`select <项目> <轮次> A` 选方向；`select <项目> <轮次> --approve` 通过整组。

- 已经可以：登记选择，转到下一角色或下一阶段。
- 要新的图：开新轮，沿上轮方向发展用 --based-on。整组只补不通过的图位用 --slots。
- 重新生成：新建同阶段轮次，写清要改的地方；旧轮仍保留，但受影响的下游选择会失效，HTML 会更新。重做系列第一只的风格时，其余同阶段角色也要重新确认。
- 改产品形态或造型时先核对影响范围，退到最早受影响阶段，并让用户重新确认受影响的后续定稿。

## 失败恢复

生图中断先查看已有文件、round.json 和调用回执，只补缺图。接口已收到成功响应时用 image_api.py resume 仅补下载，不需要 Key；没有成功响应时先核对服务端，不能重发可能已接受的付费请求。

缺图可登记为 missing 方便展示，但 missing 不能 select。透明、比例或角色身份没过检查也不能进入发帖。

最后一组和文案整理好后，仍把「已完成、补新图、重新生成」的选择交给用户。
