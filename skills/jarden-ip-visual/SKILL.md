# jarden-ip-visual

交付能够连续浏览、直接发帖的一套原创 IP 视觉素材。先把用户的想法变成稳定的角色，再把角色放进可信的产品和生活场景。图片质量、角色一致性和每张图的用途都要检查。

## 开始或恢复

1. 找到会话里已经建立的项目目录，运行 `<python> <skill>/scripts/project.py show <项目>`，从 `next` 继续。没有项目时用 `init <项目> --input <图> --kind <类型>` 建立；文字想法用 `--kind text`。输入类型见 [项目状态](references/project-state.md)。
2. 看全部输入图，识别角色、轮廓、配色、表情、配件、图中的文字和背景。区分必须保留的角色特征与仅作灵感的风格，不把参考图里的水印、页面界面或品牌带入。
3. 把用户已说过的答案立即用 `set <项目> key=value` 保存。不要让用户重新回答已知信息。同一会话新项目可以 `init --reuse-from <上个项目>`；用户的新要求优先于旧偏好。
4. 核心状态和 HTML 只需要 Python 3.10+；图片检查、盲审准备、去底、拼版和发帖整理需要 Pillow。先检测已有环境，缺依赖时说明安装用途。`<python>` 在 macOS/Linux 通常为 `python3`，Windows 为 `py -3`。

## 一次只确认一个问题

按 `show` 的 `next.field` 依次提问，拿到回答就保存，再继续下一问。每条需要用户回答的消息只含一个问题、最多一个问号；编号选项中，推荐项排第一并写「（推荐）」。结尾用「回复编号就行，也可以直接说想法」。

| 次序 | 确认内容 | 已知信息的处理 |
| --- | --- | --- |
| 1 | 产品形态：毛绒、手办、拼图或其他 | 用户说了品类就直接写 `answers.product_form`；其他品类的具体名称写入 `brief.product_detail` |
| 2 | 图中哪些主体要做 | 一个角色直接记 `single`；复杂图逐个列出角色，并提供几个角色和全部的选择，房屋道具不自动算角色 |
| 3 | 笔记类型 | 列出下面四类及简介；根据目的推荐，不能只列名称 |
| 4 | 总共做几个角色或概念 | 和每轮方向数分开；每个角色分别确认，多角色已明确选择全部时沿用已确认数量 |
| 5 | 整套发帖或九宫格 | 整套包含顺序图、标题、正文、tag；九宫格是正好九张再附拼图预览 |

四类选项按情况重排推荐顺序：

- **同系列合集**：风格统一的全家福、逐只展示和使用场景，适合系列出道、测款和预热。
- **IP 设计手稿**：成品首图、三视图、手稿过程、世界观场景和延展，适合设计师作品展示。
- **单个玩偶多维展示**：围绕一个主角展示认脸、尺度、材质、角度和用法，适合单款上新。
- **多个玩偶多场景展示**：一组角色共同生活，从合照到居家、主题场景和出门，突出关系与集齐欲。

拼图等品类可把「玩偶」替换为「产品」，保留相应图片的功能。信息矛盾或需求改变时只追问当前会影响结果的一项，其他答案保留。

## 选定图片能力

优先使用宿主内置生图能力，其次用已连接的图片服务，最后才询问兼容接口地址和模型。优先可用的较新高质量图像模型，通过能力发现核实，不在流程里写死「最新」版本号。选择结果写入 `image_backend`。

内置或已连接能力可用时，直接使用，不向用户索取额外 Key。按真实工具说明提交参考图；拿到输出路径后把图片复制进当前轮目录，再目视检查。工具未返回图不算成功。

第三方接口按 [图片后端](references/image-backends.md) 查询本地配置和脱敏凭据状态。已有 Key 直接复用；缺失时启动随附输入页，让用户亲自保存，Key 不进聊天。地址、模型是普通设置，和系统凭据分开保存。

生图不可用时保存方向和提示词，用 `record-round --allow-missing` 生成明确标注缺图的 HTML；说明停在生图这一步。仍给一个三选一问题：文字方向已经可以并保留某方向意向、要新的方向、重新生成本轮方案。意向写入 notes，缺图补齐之前不能 select 或推进；不能把占位、代码绘制或旧图当作新生成的图片。

## 每轮如何执行

1. 读取 [阶段规则](references/stages.md)、当前的 [笔记类型](#按需读取) 和 [提示词与视觉验收](references/prompting.md)。以 `show` 的当前主体和阶段为准开 `new-round`；默认每轮三个方向，用户偏好可改为三到五个。
2. 填写新建 `round.json` 每项的 `title`、`idea`、完整 `prompt`，按 `refs` 带原图、上轮定稿和系列风格参考。方向必须在轮廓、材质或场景策略上有实质差异；每项单独出图。
3. 真实调用图片能力，保存成各项 `image` 指定的文件。按 [材质规则](references/product-forms.md) 检查形态和一致性；场景轮每张备选、整组、编辑和合成图都必须按 [零上下文物理审查](references/physics-review.md) 交给独立 Agent。缺审、失败或不确定不能登记或选定，问题只重做对应项。
4. 通过目视检查后运行 `record-round <项目> <轮次>`，再运行 `build_gallery.py <项目>`。HTML 展示参考、当前方向、历史和已选图；它不能替代生图。
5. 回复可点击的本地 HTML 路径，只问一题，给三个编号选项：① 已经可以（推荐），指定方向或整组通过；② 要新的图，沿指定方向补变化或只重做几张；③ 重新生成，整轮重做。不要只问「喜欢哪个」而漏掉继续生成的入口。
6. 用户选定后运行 `select`。要新图或重做时用新轮次，沿某方向发展加 `--based-on <轮次>:<方向>`；重建 HTML，并再次交给用户确认。没有用户的选定就不进入后续阶段。

## 阶段与多角色

顺序是概念 → 材质方向 → 完整 2D 透明图 → 场景 → 发帖整理。线框、草图或文字先做概念；输入已是完整设计且用户明确认可时，用 `accept-input` 登记概念，再做材质，不能把草图当作材质定稿。

概念数量指要做的角色或设计数量；方向数量指同一角色本轮的备选。多角色先定第一只的比例、五官和工艺语言，其余逐只生成、分别确认。后续角色带第一只定稿作风格参考，保留各自原图的身份特征。

透明图是完整正面全身的 PNG 图片资产，保持已选材质，不是三维模型。先调用生图，再用 `check_images.py --alpha` 检查；若工具不支持真透明，用反差纯色背景生成后运行 `remove_bg.py`，重新看毛边和孔洞。通过这组资产后才开场景。

场景先用三个方向定光线与道具，再按笔记结构制作整组。尺度靠手、桌面等可见参照，不靠“仅供示意”图字。支撑、重力、柔性连接、环扣、人体接触、光影都须逐图盲审；不能以整体好看、隐藏支架或文案解释放过局部物理问题。这是视觉审查，不冒称数值物理仿真；没有隔离看图能力就停在待审，不自批。

## 整理发帖素材

1. 用场景整组的 `select --approve` 登记定稿；只重做不满意的图时加 `--skip <图位>`。逐张检查故事顺序、角色一致性、材质和像真实照片的程度。
2. 按 [文案规范](references/copywriting.md) 写 `copy.json`。正文对应已生成的图；尺寸、价格、授权、打样和发售时间只写有依据的信息。tag 按所选类型的类别顺序排列，不复制参考帖的品牌与活动。
3. 默认交付干净图片，不加“AI效果图、非实拍、仅供尺度示意、尺寸待定”等声明或提示条；未知信息和真实性说明只放文案、HTML及平台声明。只有用户明确要图字才用 `compose.py` 或 `overlays`，后者须设 `image_text=user-approved`；仍禁伪字。拼版标 `method=compose/derive` 和 `sources`，不冒称新生图。
4. 运行 `package_post.py <项目> --dry-run`，再 `--prepare-review` 生成实际待发布图，逐张独立物理审查通过后正式打包；详见 [物理审查](references/physics-review.md)。结果是 `post/` 编号 3:4 图片、`caption.md`、`manifest.json`，九宫格另有预览。旧版保留，再运行 `check_images.py <项目>/post --ratio 3:4 --min-side 1080` 和 `build_gallery.py`。
5. 交付 HTML、发帖目录、透明资产和文案路径。说明是 AI 设计效果图，提醒在发布页核对平台限制并开启 AI 声明。最后仍提供三选一：已完成（推荐）、补新图、重新生成；不替用户发布。

## 阶段后的可选延展

本轮已经在问三选一时不再加问题。用户明确收尾且适合继续时，从下表最多选三项，首项标推荐，并说清代价；已授权的下一步直接执行。

| 当前交付 | 可选下一步与代价 |
| --- | --- |
| 一套定稿 | 补一个真实用法场景：增加一轮生图，可能收费 |
| 发布素材 | 做九宫格：复用已有图，缺的图才调用生图 |
| 系列素材 | 延展一个角色：沿用风格，但需要逐只确认和额外生图 |
